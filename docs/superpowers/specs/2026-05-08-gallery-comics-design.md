# Gallery Comics Design

## Goal

Make comics a first-class gallery experience without adding a separate Comics entity. Folder galleries, zip archives, and cbz archives should all scan into the same gallery/image model, while comic-aware galleries gain richer metadata, natural page ordering, archive-native reading, and a dedicated reader UI.

## Current Context

Obscura already has the foundation for archive galleries:

- `@obscura/media-core` discovers `.zip`, `.cbz`, and `.cbr` files and can list/extract zip members.
- The database has `galleries.gallery_type = "zip"` and `galleries.zip_file_path`.
- Archive member images are stored as `archive.cbz::member/path.jpg`.
- Image thumbnails are generated by extracting archive members to temporary files.
- Full image assets can be served directly from archive members through `/assets/images/:id/full`.

The gaps are metadata import, natural numeric page ordering, cover fallback behavior, parent-gallery cover tiling, aspect-aware gallery thumbnails, gallery-detail browsing controls, and the comic reader.

## Scope

This work keeps comics under Galleries. A gallery is comic-aware when:

- `galleryType === "zip"` and the archive extension is `.zip` or `.cbz`.
- A `ComicInfo.xml` file exists inside the archive.
- A folder gallery contains a `ComicInfo.xml` file.

`.cbr` is not part of this first pass because the existing helper treats archive formats through zip APIs, and cbr/rar support needs a different extraction path.

## Metadata

`ComicInfo.xml` should map into existing gallery fields where possible:

- `Title` -> `galleries.title`
- `Summary` -> `galleries.details`
- `Web` -> `galleries.urls`
- `Year`, `Month`, `Day` -> `galleries.date` when a valid date can be built
- `Publisher` or `Imprint` -> studio
- `Writer`, `Penciller`, `Inker`, `Colorist`, `Letterer`, `CoverArtist`, `Editor`, `Translator` -> performers
- `Genre`, `Tags`, `Characters`, `SeriesGroup`, `StoryArc`, `Manga`, and `AgeRating` -> tags

The scanner should preserve explicit user edits where Obscura already has a value that is likely user-owned. Initial archive/folder import can seed metadata; rescans should not repeatedly overwrite non-empty fields unless the row still has scanner-derived defaults.

Comic-specific fields should also be available to the detail UI as a read-only comic info block. The first pass can derive this block from a JSON metadata column or from a normalized helper result stored on the gallery row. It should include fields such as `series`, `number`, `count`, `volume`, `pageCount`, `language`, `format`, `manga`, `ageRating`, and creator names.

In comic-aware UI contexts, performers should be labeled as **Authors**.

## Ordering

Comic page ordering must use natural filename sorting. Examples:

- `1.png`, `2.png`, `9.png`, `10.png`
- `page 001.jpg`, `page 002.jpg`, `page 010.jpg`

Natural ordering should be available as an image sort option and should be the default for archive/comic galleries. Plain folder galleries can keep their existing default unless `ComicInfo.xml` is present.

The archive scanner should insert images with natural sort order by default so readers work even before the user touches sort controls.

## Gallery Detail Browsing

Gallery detail should use the shared `MediaSurface` pattern as a scoped Images view:

- Same toolbar family as Images: search, sort, filters, saved presets, view-mode toggle, thumbnail size, infinite loading, and bulk actions.
- Scoped fetches should pass `gallery=<id>` to the Images API.
- View modes should include:
  - **Masonry**: the current tiling mode, preserving page aspect ratio.
  - **Grid**: stable page cards that still respect the page image ratio instead of forcing square crops.
  - **List**: compact rows for management and bulk actions.
- Gallery-specific actions remain available: edit gallery metadata, import/upload for folder galleries, choose/reset covers, delete, and bulk image actions.

Gallery thumbnail presentation should no longer assume a square crop. If a gallery cover resolves to a portrait comic page, the thumbnail shell should preserve a portrait-friendly aspect ratio where the layout supports it.

## Covers And Preview Tiling

Cover selection should work in priority order:

1. Uploaded custom gallery cover.
2. Explicit `coverImageId`.
3. First naturally sorted direct image in the gallery.
4. For parent/container galleries with child galleries, a tiled preview made from each child gallery's resolved first/cover image.
5. Existing gradient fallback.

The `/assets/galleries/:id/cover` path should fall back to the first image instead of returning 404 when no explicit cover exists. Parent gallery cards and sub-gallery sections should receive preview paths that represent child gallery covers when the parent has no direct images.

## Comic Reader

Archive/comic galleries should expose a dedicated reader built from the current image lightbox foundation, but optimized for page reading.

Reader modes:

- **Paged mode**
  - Single-page view.
  - Two-page spread view.
  - `First Page is Cover` toggle. When enabled, page 1 is shown alone, then pages pair as 2-3, 4-5, and so on.
  - Keyboard and touch navigation should move by one spread in two-page mode.

- **Webtoon mode**
  - Vertical scroll.
  - Pages render in a continuous column with minimal gaps.
  - Uses the same archive-backed full image URLs, so cbz/zip files stay on disk.

Reader controls should follow the Dark Room design language: sharp corners, glass overlay controls, brass glow only for active states, and no hover-only core actions.

## Data Flow

1. Gallery scan discovers loose images and zip/cbz archives.
2. Folder or archive ComicInfo is parsed when present.
3. The scanner upserts the gallery row, seeds metadata, upserts authors/tags/studio, and indexes images in natural page order.
4. Image thumbnail jobs generate per-page thumbnails from either disk files or archive members.
5. Gallery detail loads the gallery metadata plus an initial image page.
6. `MediaSurface` fetches more scoped images through the existing Images API with gallery-specific sort defaults.
7. The reader consumes the loaded page list and can request more pages as needed.

## Error Handling

- Bad or missing `ComicInfo.xml` should not fail a scan. The gallery should still import with filename-derived title and page list.
- Unsupported archive members should be ignored.
- Missing archive files should be handled by the existing visibility and stale cleanup paths.
- If direct archive member serving fails, the asset route should return 404 for that image, not fail the whole gallery.
- The reader should show a graceful empty/error state when no readable pages are available.

## Testing

Tests should cover:

- Natural filename sorting.
- ComicInfo parsing from XML text.
- Zip/cbz member ordering and metadata extraction from the sample ComicInfo shape.
- Gallery cover fallback to the first image.
- Parent-gallery preview tiling using child gallery covers/first images.
- Images API natural sort option.
- Gallery-scoped `MediaSurface` configuration defaults for comic vs non-comic galleries.
- Comic reader spread math, including first-page-cover behavior.
- Svelte validation/autofix for new or changed Svelte components.

## Out Of Scope

- A separate Comics entity or top-level navigation section.
- Full rar/cbr extraction support.
- Editing every ComicInfo-specific field in the UI.
- Writing metadata back into archives.
